Kookaburra

Query Java objects like a database: bitmaps underneath, streams on top.

An embedded object database for Java 17+. Store plain annotated objects and query them with a type-safe, Stream-like API or JPQL-style OQL. Filters, sorts and aggregates run on RoaringBitmap indexes over memory-mapped segments, with transactions at three isolation levels, unique and foreign-key constraints, exact decimals and online backup.

Why Kookaburra

Local data shouldn't need a server or an ORM

Typical pain points when an application needs to keep and query its own objects:

🧱

ORM + SQL for local state

Mapping layers, schemas and a database server just to persist and filter your own objects.

🐢

Streams over lists don't scale

list.stream().filter(...) scans everything, every time, and lives only in the heap.

🔤

Stringly-typed queries

Field names in strings break silently when you refactor.

🔍

No way to look inside

Binary stores give you nothing to browse, fix or export data with.

🧹

Integrity by hand

Duplicate keys and dangling references slip in when every check lives in application code.

⚖️

Races between checks and writes

"Check, then write" breaks under concurrency: two writers both see the old state.

💸

Floating-point money

0.1 + 0.2 is not 0.3 in a double.

💾

Backing up a live store

Copying files while the application writes gives an inconsistent copy.

Features

Everything in one small library

Embedded, durable, indexed and queryable, with a desktop tool to look inside.

🧭

Type-safe chained queries

query(Book.class).where(Book::getYear).ge(1960).list() or the generated Book_ metamodel. Refactoring-safe.

⚡

Bitmap indexes

Roaring postings, sorted dictionaries and value-sorted docs: millisecond filters on 10 M objects.

🔤

OQL

JPQL-style SELECT / UPDATE / DELETE with the SQL-92 core: CASE, LIKE, DISTINCT, GROUP BY … HAVING.

🧬

Nested objects

Inheritance, embedded objects at any depth, lists and maps of them (whereAny, MEMBER OF), references with fetch.

🔁

Transactions

READ COMMITTED, SNAPSHOT, SERIALIZABLE; optimistic, never blocking; retries built in.

🔑

Unique constraints

@Unique on any scalar field; checked atomically at commit.

🔗

Foreign keys

@ForeignKey with RESTRICT, CASCADE or SET_NULL; backlinks with referrers.

💰

Exact decimals

BigDecimal fields, indexed and compared by value; exact SUM and arithmetic.

🪝

Lifecycle callbacks

@PrePersist, @PostLoad and friends, plus entity listeners.

💾

Online backup

A consistent snapshot while writers keep going; restore = open.

📦

Large values

Long texts and binaries such as images, MiB-sized, through flush, compaction and reopen.

🛡

Durable & consistent

WAL with group commit, crash recovery, MVCC snapshots, atomic batches, optimistic locks; deleted space is reclaimed.

🧩

Dynamic API

A self-describing schema with evolution. Open any database without its classes.

🗜

Compact & fast restart

Zero-copy mmap segments, ~150 B / object, 2.0 ms reopen, 6.5 MiB heap for 10 M objects.

🖥

Kookaburra Studio

Several databases, transactions at any level, backlinks, constraints, image preview, OQL console, backup. One jar for every OS.

💽

Tested on disk

Every shared suite runs in memory and on disk; ≥ 90% coverage; a 10 M-object stress run.

How it works

An LSM store with bitmap-indexed segments

  • All three APIs compile to the same predicate plan. The planner pushes conditions down to postings and ordinals and orders them by cost.
  • Writes are encoded on the caller's thread. A single sequencer logs each group to the WAL with one fsync, applies it to lock-free MemSegments and publishes a new snapshot.
  • Before the WAL, the sequencer checks conflicts (and SERIALIZABLE reads) and constraints; cascades join the same commit.
  • MemSegments flush to immutable, memory-mapped segment files, and tiered compaction merges them in the background.
Quick start

Three steps

Add the dependency, annotate a class, query it.

1 · pom.xml
<dependency>
    <groupId>com.github.paganini2008</groupId>
    <artifactId>kookaburra-core</artifactId>
    <version>1.0.0-SNAPSHOT</version>
</dependency>
2 · Entity
@Entity
public class Book {
    @Id long oid;
    @Version long version;
    @Index String title;
    @Index Genre genre;
    @Index(IndexKind.ORDINAL) int year;
    double price;
    // constructors, getters …
}
3 · Store & query
try (ObjectDB db = ObjectDB.open(Path.of("data"))) {
    db.batch()
      .insert(new Book("Dune", Genre.SCIFI, 1965, 9.99))
      .insert(new Book("Neuromancer", Genre.SCIFI, 1984, 12.50))
      .insert(new Book("Hyperion", Genre.SCIFI, 1989, 14.20))
      .commit();

    List<Book> books = db.query(Book.class)
            .where(Book::getGenre).eq(Genre.SCIFI)
            .where(Book::getYear).ge(1960)
            .orderBy(Book::getYear).desc()
            .limit(2)
            .list();
    System.out.println(books.stream().map(Book::getTitle).toList());
}
Output
[Hyperion, Neuromancer]
Examples

Use cases

Each example: input → code → output, from a real run on six books.

Group & aggregate

Count and average price per genre.

db.query(Book.class)
  .groupBy(where(Book::getGenre))
  .agg(Q.count().as("books"),
       Q.avg(where(Book::getPrice)).as("avgPrice"))
  .toList();
SCIFI books=4 avg=11.36 FANTASY books=1 avg=10.00 CRIME books=1 avg=7.40

OQL for tools & scripts

JPQL-style text queries with parameters.

db.oql("SELECT b.author, b.year FROM Book b " +
       "WHERE b.year < :y ORDER BY b.year")
  .param("y", 1950).rows();
J.R.R. Tolkien 1937 Raymond Chandler 1939

Generated metamodel

Compile-time field constants from the annotation processor.

db.query(Book.class)
  .filter(Book_.tags.contains("classic"))
  .filter(Book_.price.lt(10.0))
  .count();

Admin without classes

Dynamic access to any stored class.

DynamicCollection books = db.dynamic("Book");
books.from()
  .where("author").startsWith("J")
  .list().get(0).get("title");

Safe concurrent edits

Optimistic locking with @Version.

dune.setPrice(11.99);
db.update(dune);
// OptimisticLockException if changed meanwhile
dune=11.99

See the plan

Which index answers each condition.

db.query(Book.class)
  .where(Book::getGenre).eq(SCIFI)
  .where(Book::getYear).between(1950, 1970)
  .explain();
genre = 'SCIFI' [sorted docs card=3] year IN [1950, 1970] [sorted docs card=6]

Transactions

Opt-in transactions; conflicts are detected at commit.

try (Transaction tx = db.begin(Isolation.SNAPSHOT)) {
  Account a = tx.get(Account.class, from);
  tx.update(a.balance(a.getBalance() - 30));
  tx.increment(Account.class, to, "balance", 30);
  tx.commit();
}
ConflictException if `a` changed meanwhile

Nested objects

Paths into embedded objects, lists and maps.

db.query(Shipment.class)
  .whereAny(Shipment::getItems, Item::getSku)
  .contains("pear").list();
db.oql("SELECT s FROM Shipment s " +
       "WHERE 'kiwi' MEMBER OF s.items.sku").list();
[S-1] [S-2]

Constraints & decimals

Unique numbers, cascading foreign keys, exact totals.

@Unique String number;
@ForeignKey(onDelete = OnDelete.CASCADE)
Ref<Customer> customer;
@Index BigDecimal total;

db.query(Order.class).sum(where(Order::getTotal));
duplicate 'A-1' → ConstraintViolationException sum of 19.90 + 10.15 → 30.05

SERIALIZABLE

Two on-call doctors both try to go off call.

db.inTransaction(TxOptions.defaults()
    .isolation(Isolation.SERIALIZABLE), tx -> {
  if (tx.query(Doctor.class).where(Doctor::isOnCall)
        .eq(true).count() > 1)
    tx.update(tx.get(Doctor.class, me).offCall());
});
second commit: serialization failure, retried one doctor stays on call
