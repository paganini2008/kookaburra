Embedded object database for Java

Query Java objects like a database.

Store plain annotated objects in your application, then query them with a type-safe API or SQL-style OQL. Indexes, transactions, constraints, full-text and vector search in one library. No server, no ORM, no schema scripts.

Tutorial

Kookaburra in three minutes

Studio with the mouse, then the same features as Java code. English subtitles.

Why Kookaburra

Local data shouldn't need a server or an ORM

Typical pain points when an application keeps and queries its own objects, and what Kookaburra does instead.

🧱

ORM + SQL for local state

Mapping layers, schemas and a server just to persist your own objects.

✓ annotate the class, call insert
🐢

Streams over lists don't scale

list.stream().filter(...) scans everything, every time.

✓ indexes answer in milliseconds
🔤

Stringly-typed queries

Field names in strings break silently when you refactor.

✓ method references and a generated metamodel
🔍

No way to look inside

Binary stores give you nothing to browse, fix or export.

✓ Kookaburra Studio for every database
🧹

Integrity by hand

Duplicate keys and dangling references slip in.

✓ @Unique and @ForeignKey, checked at commit
⚖️

Races between checks and writes

Two writers both see the old state.

✓ transactions up to SERIALIZABLE
🧠

A separate search stack

A search server and a vector database next to your data.

✓ BM25 and HNSW built in, local Ollama models
💾

Backing up a live store

Copying files while writing gives a broken copy.

✓ db.backup(dir), consistent, online

How it works

A library inside your application

Kookaburra runs in your JVM. Data lives in one directory, or only in memory.

  1. Annotate plain classes. No server, no schema scripts.
  2. Query with method references or OQL; indexes answer, explain() shows which one.
  3. Write objects, batches or transactions: atomic and durable, constraints checked at commit.
  4. Search words and meanings in the same query.
  5. Look inside with Studio; db.backup(dir) while the application runs.

Quick start

Running in three steps

Add the dependency, annotate a class, query it.

1 · pom.xml
<dependency>
    <groupId>com.github.paganini2008</groupId>
    <artifactId>kookaburra-core</artifactId>
    <version>1.0.0-SNAPSHOT</version>
</dependency>
1 · build.gradle
implementation 'com.github.paganini2008:kookaburra-core:1.0.0-SNAPSHOT'
2 · Entity
@Entity
@Comment("A book in the shop")
public class Book {
    @Id long oid;
    @Version long version;
    @Index String title;
    @Index Genre genre;
    @Index(IndexKind.ORDINAL) int year;
    double price;
    // constructors, getters …
}
3 · Store & query
try (ObjectDB db = ObjectDB.open(Path.of("data"))) {
    db.batch()
      .insert(new Book("Dune", Genre.SCIFI, 1965, 9.99))
      .insert(new Book("Neuromancer", Genre.SCIFI, 1984, 12.50))
      .insert(new Book("Hyperion", Genre.SCIFI, 1989, 14.20))
      .commit();

    List<Book> books = db.query(Book.class)
            .where(Book::getGenre).eq(Genre.SCIFI)
            .where(Book::getYear).ge(1960)
            .orderBy(Book::getYear).desc()
            .limit(2)
            .list();
    System.out.println(books.stream().map(Book::getTitle).toList());

    System.out.println(db.oql("SELECT b.title FROM Book b WHERE b.year < 1970").list());
}
Output
[Hyperion, Neuromancer]
[Dune]

kookaburra.embedder=ollama

Real code, real output

Each example: code → output, from real runs.

Group & aggregate

Count and average price per genre.

db.query(Book.class)
  .groupBy(where(Book::getGenre))
  .agg(Q.count().as("books"),
       Q.avg(where(Book::getPrice)).as("avgPrice"))
  .toList();
SCIFI books=4 avg=11.36 FANTASY books=1 avg=10.00 CRIME books=1 avg=7.40

OQL for tools & scripts

Text queries with parameters.

db.oql("SELECT b.author, b.year FROM Book b " +
       "WHERE b.year < :y ORDER BY b.year")
  .param("y", 1950).rows();
J.R.R. Tolkien 1937 Raymond Chandler 1939

Generated metamodel

Compile-time field constants from the annotation processor.

db.query(Book.class)
  .filter(Book_.tags.contains("classic"))
  .filter(Book_.price.lt(10.0))
  .count();
2

Nested objects

Paths into embedded objects, lists and maps.

db.query(Shipment.class)
  .whereAny(Shipment::getItems, Item::getSku)
  .contains("pear").list();
db.oql("SELECT s FROM Shipment s " +
       "WHERE 'kiwi' MEMBER OF s.items.sku").list();
[S-1] [S-2]

One element, every condition

Like $elemMatch: the same list element matches.

db.query(Shipment.class)
  .whereElement(Shipment::getItems, e -> e
      .where(Item::getSku).eq("A")
      .where(Item::getQty).gt(5))
  .list();
// OQL: ... FROM Shipment s JOIN s.items i
//      WHERE i.sku = 'A' AND i.qty > 5
only shipments with one item "A" × more than 5

Query plans

Which index answers, rows in → out, time per step.

db.query(Person.class)
    .where(Person::getCity).eq("Perth")
    .limit(10)
    .explainAnalyze();
a tree of steps: index or scan, rows in → out, time, slowest marked

Vector search

The closest documents to an embedding, after a filter.

List<Doc> top = db.query(Doc.class)
    .where(Doc::getLang).eq("en")
    .nearest(Doc::getEmbedding, q, 10)
    .list();
top 10 of 100,000 vectors (384 dims): about 1 ms, 99.6 % same as exact

Search by text

Distance functions named as in pgvector; embed asks a local Ollama model.

SELECT d.title,
  cosine_distance(d.embedding,
    embed('bread at home')) AS dist
FROM Doc d WHERE d.lang = 'en'
ORDER BY dist LIMIT 10
runs as the same vector search

Hybrid, diverse, rerank

Words and meanings fused, near-duplicates dropped, a local model re-orders.

db.query(Doc.class)
  .nearest(Doc::getEmbedding, "baking bread", 10)
  .hybrid(Doc::getBody)     // RRF
  .diverse()                // MMR
  .rerank(Doc::getBody)     // Ollama model
  .list();
RAG retrieval without a search server

Full-text search

Every word, a phrase, or the most relevant first (BM25).

db.query(Article.class)
    .where(Article::getBody)
    .matches("\"sourdough bread\"").list();
db.query(Article.class)
    .search(Article::getBody, "baking bread", 10)
    .list();
OQL: MATCH(a.body, 'bak*'), SCORE(…), HIGHLIGHT(…)

Int8 vectors

A quarter of the memory for the index, re-ranked exactly.

@Vector(dim = 384,
        quantization = VectorQuantization.INT8)
float[] embedding;
same answers, 4 × smaller index

Transactions

Opt-in transactions; conflicts are detected at commit.

try (Transaction tx = db.begin(Isolation.SNAPSHOT)) {
  Account a = tx.get(Account.class, from);
  tx.update(a.balance(a.getBalance() - 30));
  tx.increment(Account.class, to, "balance", 30);
  tx.commit();
}
ConflictException if `a` changed meanwhile

SERIALIZABLE

Two on-call doctors both try to go off call.

db.inTransaction(TxOptions.defaults()
    .isolation(Isolation.SERIALIZABLE), tx -> {
  if (tx.query(Doctor.class).where(Doctor::isOnCall)
        .eq(true).count() > 1)
    tx.update(tx.get(Doctor.class, me).offCall());
});
second commit: serialization failure, retried one doctor stays on call

Constraints & decimals

Unique numbers, cascading foreign keys, exact totals.

@Unique String number;
@ForeignKey(onDelete = OnDelete.CASCADE)
Ref<Customer> customer;
@Index BigDecimal total;

db.query(Order.class).sum(where(Order::getTotal));
duplicate 'A-1' → ConstraintViolationException sum of 19.90 + 10.15 → 30.05

Safe concurrent edits

Optimistic locking with @Version.

dune.setPrice(11.99);
db.update(dune);
// OptimisticLockException if changed meanwhile
dune=11.99

Durability per write

Fast bulk loads, safe payments, in the same database.

WriteBatch b = db.batch().durability(Durability.ASYNC);
events.forEach(b::insert);
b.commit();
db.inTransaction(TxOptions.defaults()
    .durability(Durability.SYNC), tx -> pay(tx));
one disk flush per batch; payments on disk at commit

Rename without migration

Fields and classes keep their stored data.

@Entity @Renamed("com.example.Client")
public class Customer {
    @Id long oid;
    @Renamed("fullName") String name;
}
old data read under the new names

Export the schema as Java

Entity classes with annotations, comments, getters and setters.

db.exportSchema(Path.of("src/main/java"), null);
// or another package (classes get @Renamed):
db.exportSchema(Path.of("src/main/java"),
                "com.acme.model");
compiles and opens the same database, no new schema version
